Question. Within MMR-deficient tumours, what does aneuploidy track — mutation status, or cell-type composition — and does either answer move when the aneuploidy cut does? Cohort. MMR-deficient only (n = 110), every aneuploidy-class figure drawn at both cuts (0.1 and 0.2), with one marked exception: the interaction model, which cannot be estimated inside a single stratum. Reads. The master (built on demand by get_master()), the long MAF, and the FlowPath annotation tree. Out of scope. Anything on the full cohort. Aneuploidy against TMB across both MMR strata -> 06-tmb. The same composition panels keyed on treatment response -> 05-response. Why there are two cuts and why both are reported -> 00-methods.

The restriction is the point. MMR deficiency is itself a route to genomic instability, so in the whole cohort any variable that tracks MMR status will also appear to track aneuploidy. Conditioning on MMRd removes that shortcut. The outcome in every figure is the same continuous aneuploidy score; what changes is the grouping on the x-axis — mutation status in Part 1, cell-type composition in Part 2. The cohort definition, the two aneuploidy cuts and the highlight colours are in 00-methods.

The two cuts, 0.1 and 0.2, split this report in two ways. Part 1 puts the score on the y axis and mutation status on the x axis, so its panels are the same at either cut and both cuts are drawn as dashed lines across them. Part 2 puts the class on the x axis, so every one of its figures is drawn at both cuts — the two cuts are the columns of each figure, and each column carries its own test. Raising the cut can only move a patient from the high box to the low box, so the columns are nested rather than independent: only patients scoring between the cuts move.

The gene panel, spelled out

Genes are tested one at a time, each in its own panel, so a signal is attributable to a specific gene rather than to a union that could be driven by whichever gene is most frequently mutated. Two groups, kept deliberately separate:

Group Genes Why they are grouped this way
MMR panel PMS2, MLH1, MSH2, MSH6, MSH3 Loss of any of these causes mismatch-repair deficiency. MSH3 pairs with MSH2 to form MutSb.
Wnt / b-catenin CTNNB1, APC An independent oncogenic pathway, not an MMR mechanism.
TP53 TP53 Handled separately: it is already a first-class column on the master.

The MMR union (panel-altered = at least one pathogenic variant in any MMR panel gene) is shown last, after the per-gene panels. CTNNB1 and APC are deliberately excluded from that union, because folding them in would change what “panel-altered” means everywhere else in the pipeline. There is no Wnt union: with two genes the per-gene panels already show everything a union would.

P-values come from stat_compare_means(), Wilcoxon rank-sum for two groups and Kruskal-Wallis for more, uncorrected across panels. With one test per gene, treat them as descriptive.

Data

Two sources, joined on pid. The aneuploidy score and its derived classes come from attend_master_joined. The mutation status is recomputed here directly from the long MAF rather than taken from the master’s collapsed columns, because the average of a variant row is meaningless; pathogenic_by_patient() and mutation_status_long() are the same helpers 01-data-integration used, so the two cannot drift. Crossing the crosswalk against the full gene list guarantees every gene gets a column even when it never appears in the MAF, with unmutated patients FALSE rather than NA.

cw  <- build_barcode_pid(load_gianlu_clinical_data(), make_id_cfg())
maf <- read_intermediate("maf_data")

mut <- pathogenic_by_patient(maf, cw)   # pid, TP53_pathogenic, panel_pathogenic (MMR union)

# Per-gene status for the one-gene-at-a-time panels: MMR panel + Wnt genes.
#
# ⚠️ NO replace_na(mutated, FALSE) HERE. It used to sit on the line below, and it turned
# every patient the MAF never reached — and every gene that was never statused — into
# "<GENE>-wt". Combined with the loader statusing only TP53, that made all five MMR panels
# and both Wnt panels a single wild-type box, captioned as though the comparison had been
# made. An uncalled gene is NOT a wild-type gene; the class stays NA so the panel drops the
# patient, and gene_called below reports how many were dropped and why.
gene_long <- cw |> distinct(pid) |>
  tidyr::crossing(gene = attend_genes_per_gene) |>
  left_join(mutation_status_long(maf, cw), by = c("pid", "gene")) |>
  mutate(class = if_else(mutated, paste0(gene, "-mut"), paste0(gene, "-wt")))  # NA stays NA

gene_status <- gene_long |>
  select(pid, gene, class) |>
  pivot_wider(names_from = gene, values_from = class, names_glue = "{gene}_class")

# The denominator behind every per-gene panel below: how many patients this gene could
# actually be called in. A gene with 0 called is reported as a skip, never drawn.
gene_called <- gene_long |>
  group_by(gene) |>
  summarise(called    = sum(!is.na(class)),
            uncalled  = sum(is.na(class)),
            mutated_n = sum(class == paste0(gene, "-mut"), na.rm = TRUE),
            .groups = "drop")

dat_all <- master |>
  select(-any_of(c("TP53_pathogenic", "panel_pathogenic"))) |>  # recompute here
  left_join(mut, by = "pid") |>
  left_join(gene_status, by = "pid") |>
  mutate(
    aneuploidy_value = suppressWarnings(as.numeric(.data[[attend_cols$aneuploidy]])),
    TP53_class  = if_else(TP53_pathogenic,  "TP53-mut",     "TP53-wt"),
    panel_class = if_else(panel_pathogenic, "MMR-panel-altered", "MMR-panel-wt")
  )

Part 2 — aneuploidy by cell-type composition

Cell types and normalization

“Cell type” is phenotype_clean, the parenthetical phenotype label in the FlowPath export (changeable in code/load_phenotypes.R). Every count is taken inside the annotated region and expressed as a fraction, but the denominator changes the question, so all three are shown:

Normalization Denominator The question it answers
all cells inside every cell in the annotation what fraction of the tissue is this cell type?
tumour cells inside tumour cells only how much of this cell type per unit of tumour?
CD45+ cells inside leukocytes only what is the composition of the immune compartment?

Each is drawn twice: the raw fraction with a Wilcoxon test, and the arcsine-square-root-transformed fraction with a two-sample t-test. Agreement between the two is reassurance; disagreement means the result depends on the test rather than the data. No multiple-testing correction is applied anywhere in this report, and with one test per cell type per normalization that is many comparisons, so every p-value here is descriptive.

Cell-type composition by aneuploidy class

One row per cell type and one column per aneuploidy cut, aneuploidy-high vs -low within each, over MMRd only, from the ct table built above. Each normalization is shown as a raw-fraction/Wilcoxon figure followed by its arcsine/t-test companion, and every test is computed inside its own panel, so the left and right columns are separate tests and are never pooled. Moving the cut moves patients from the high box to the low box and nothing else: the fractions on the y axis are the same numbers in both columns, so a contrast that survives the move is one the threshold is not making.

Each normalization is drawn twice: first the cell types in attend_ihc_focus (T cytotoxic, T helper, Macrophages, M1) on an axis of their own, then every cell type on one axis. The focus figure exists because Tumor reaches ~1.0 on the arcsine scale while all four of these sit under ~0.6, so an axis wide enough for Tumor leaves them unreadable — and these four are what the figure is for.

Every cell type is drawn in one figure per normalization, on a single shared y axis. A panel’s height therefore reads as that cell type’s abundance relative to every other one, which is the comparison the figure exists to support: Macrophages is read against T cytotoxic on the same scale, not against a rescaled axis of its own. scales = "free_y" would give each panel its own range and make a cell type at a fraction of a percent of the tissue draw the same box, in the same place, as one at half the tissue. The cost is accepted deliberately — on the tumour-cell denominator these cell types span orders of magnitude, so the rarest panels sit low against a scale set by the most abundant.

The two figures differ in one respect on purpose: the focus set shares one y axis, so those four cell types are directly comparable, while the overview gives each cell-type row its own — a row, not a panel, so the two cut columns of one cell type always stay on one axis and the only difference between them is which patients sit in which box. Over every measured cell type a single abundant one sets a ceiling the rest never approach, and panels that are boxes in the focus figure flatten to lines. Abundance is still readable from each overview panel’s own axis, and the content panels below carry it directly. The policy is attend_ihc_all_free_y.

The tumour phenotypes are excluded from that figure. The export carries them separately (PanCK+ Tumor, VIM+ Tumor), and on one shared axis a tumour phenotype near 1.0 on the arcsine scale compresses every immune panel under 0.35 into a flat line. Tumour content is reported on its own panel below, against the same denominator, so nothing is lost.

The pre-specified primary contrast

Of everything above, one comparison is designated primary: CD45+ / all cells inside, tested with the arcsine-square-root transform and a two-sample t-test. The Wilcoxon on the raw fraction is reported next to it as a companion, not a substitute. The other two normalizations, and CD3+CD45+, are secondary — they can and do degrade to a skip when counts are missing.

Naming one primary endpoint in advance is what keeps this from being a search across six panels for the smallest p-value. The endpoint is named once and tested once per cut: two cuts is two tests of one pre-specified contrast, not two chances at it, and a primary that holds at one cut and not the other is reported as exactly that.

mmrd_arcsin_t_wilcox <- function(df, metric_, denom_) {
  base <- df |> dplyr::filter(metric == metric_, denom_label == denom_, is.finite(frac))
  rows <- list()
  # One test per cut, never pooled: the two blocks hold the same patients under two
  # classifications, so a test across both would count every patient twice.
  for (lab in levels(droplevels(base$as_cut_lab))) {
    d   <- base |> dplyr::filter(as_cut_lab == lab)
    tab <- table(d$aneuploidy_class)   # a factor, so an empty arm is a 0, not a dropped name
    if (length(tab) < 2 || any(tab < 2)) {
      note_skip("MMRd ", metric_, " / ", denom_, " at ", lab,
                ": insufficient n per aneuploidy arm — no test at this cut.")
      next
    }
    t_res <- t.test(arcsin_sqrt(frac) ~ aneuploidy_class, data = d)     # primary
    w_res <- wilcox.test(frac ~ aneuploidy_class, data = d)             # companion
    cat(sprintf(paste0("MMRd %-10s / %-20s %-11s n=%d (high=%d, low=%d)  ",
                       "arcsin-t p=%.3g  Wilcoxon p=%.3g\n"),
        metric_, denom_, lab, nrow(d), tab[["aneuploidy-high"]], tab[["aneuploidy-low"]],
        t_res$p.value, w_res$p.value))
    rows[[lab]] <- data.frame(as_cut_lab = lab, n = nrow(d),
                              n_high = tab[["aneuploidy-high"]],
                              n_low  = tab[["aneuploidy-low"]],
                              t_p = t_res$p.value, w_p = w_res$p.value,
                              stringsAsFactors = FALSE)
  }
  if (!length(rows)) return(invisible(NULL))
  list(d = base, stats = do.call(rbind, rows))
}

The one model that needs MMR-proficient patients

The single exception to this report’s MMRd restriction, and it has to be: an interaction asks whether the aneuploidy effect differs between MMRd and MMRp, which cannot be estimated inside one stratum. The model is arcsin(sqrt(CD45+/all cells inside)) ~ aneuploidy_class * mmr_group, fitted on both groups from imm_all. The interaction row is the one of interest: a large coefficient there is what justifies restricting everything else to MMRd. The model has aneuploidy_class as a term, so it is fitted once per cut and the table gains a cut column — a single fit over the stacked frame would use every patient twice under two contradictory labels. No correction is applied, and nothing is pooled across the two fits.

fit_one_cut <- function(d) {
  if (!(nrow(d) > 4 && dplyr::n_distinct(d$aneuploidy_class) == 2 &&
        dplyr::n_distinct(d$mmr_group) == 2)) {
    note_skip("AS cut ", d$as_cut[1], ": not enough patients across both MMR groups and ",
              "both aneuploidy classes for the interaction model.")
    return(NULL)
  }
  fit <- lm(y ~ aneuploidy_class * mmr_group, data = d)
  tb  <- if (requireNamespace("broom", quietly = TRUE)) broom::tidy(fit) else {
    m <- as.data.frame(summary(fit)$coefficients); m$term <- rownames(m); m
  }
  cbind(`AS cut` = as.character(d$as_cut_lab[1]), tb)
}
