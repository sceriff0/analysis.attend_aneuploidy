What this report does and does not claim

Wu et al. (Immunity 58:2864–2877, 2025) intersect recurrently altered genes with a pooled CRISPR catalogue of T-cell-killing resisters and sensitizers, direction-matched. That filter is what this report borrows. Three differences from their analysis are load-bearing and are stated here rather than left for a reader to infer.

Their recurrence is a within-patient subtraction; this one is not. Wu et al. compare each patient’s progression tumour against that patient’s own pre-treatment baseline and call a gene recurrent when it changed in at least three patients. ATTEND has one tumour per patient and collapse_pid() averages to one row per patient, so there is no baseline to subtract. Nothing in this report is evidence about what a tumour acquired under treatment, and the phrase they use for that axis is deliberately absent below.

The two recurrence definitions are different constructs. Theirs is a count with no background model, which on their cohort returns about a quarter of the exome. This report’s is GISTIC’s background-corrected q, 0.25, on the stratum’s own run. A count and a peak statistic are not comparable, and no number here is compared to one of theirs.

The catalogue is melanoma- and ICI-derived. It was assembled from screens of tumour-cell killing by T cells, pooled across mouse and human models. Applying it to endometrial carcinoma is an assumption this report makes, not a result it establishes.

The catalogue

load_crispr_screens() reads the tracked TSV and applies the evidence cutoff as an argument, attend_crispr$min_measurements = 2 — Wu et al.’s own “concordant evidence in ≥ two independent measurements”, which reproduces their reported 519 resisters and 877 sensitizers exactly. The unfiltered blocks stay in the file so the cutoff is a choice that can be varied, not a property of the data. Symbols that qualify as both a resister and a sensitizer carry no direction, so they are dropped and counted here rather than resolved by whichever row a join kept.

Part 1 — MMRd aneuploidy-high

What was measured, and what could not be

The partition below is the denominator, printed before any test. Two of its lines exist because an absence must not read as a negative result. A peak gene that the 23 pooled screens never covered is unscreened, not “not a resister”: the screens do not tile the genome, so scoring an unscreened gene as a measured negative would inflate every p-value on the page. attend_crispr$universe is therefore screened — the genes this GISTIC run assayed intersected with the genes the catalogue screened. Genes sitting in both an amplification and a deletion peak carry no direction either, and are dropped on the same rule gistic_feature_direction() already applies.

Is that more overlap than chance?

A count of hits is not a result until it is read against what chance produces, and the null here has to respect two kinds of clustering at once. GISTIC peaks are contiguous blocks — an amplicon spanning 300 genes is one event, not 300 independent successes — and the catalogue is also positionally clustered, because immune genes sit in families: TAP1, TAP2, PSMB8 and TAPBP across the MHC region, the IFNA cluster on 9p21 immediately beside CDKN2A, a classic deletion peak. So the peaks are slid to random positions along the genomically ordered universe while the catalogue is held exactly where it is. Measured on simulated null data with both kinds of clustering, a hypergeometric test runs at roughly five times its nominal type-I rate and so does a test that holds the peaks and reshuffles the gene labels; the block shift is calibrated. The three measured type-I rates, and why each alternative fails, are in 00-methods; the calibration that pins them is code/tests/test_crispr_overlap.R. This is Family B, corrected with BH: the catalogue is external and fixed in advance, but the peaks come from ATTEND’s own group labels, so no result here can be promoted to a confirmatory one.

The observed and expected counts are the two numbers to read together: expected is the mean of the null, so a hit count close to it is the answer “no more than the genome’s layout already predicts”, whatever the catalogue membership looks like gene by gene. The combined row adds the two directional rows and is a summary, not a third question, so it carries no adjusted p.

How much of this rests on one patient

Report 10 reports, for each recurrent locus, the fraction of leave-one-out MMRd-high GISTIC re-runs that retain it. That column qualifies this one too: the peak set is the input here, so a functional enrichment computed on peaks that turn over when a single tumour is dropped inherits exactly that instability. The table below re-reads the leave-one-out runs and reports how many of them retain each gene’s peak, so the enrichment above can be read against the stability of the thing it was computed on rather than separately from it.

                       caption = paste0("Each hit's peak, across the leave-one-out MMRd-high ",

Part 2 — the same question in all four strata

The four MMR × aneuploidy strata answered side by side, each on its own GISTIC run, so a stratum with more peaks is not being compared against another stratum’s peak list. The universe is rebuilt per run for the same reason: a run that assayed fewer genes has a smaller denominator, and sharing one denominator across runs would move hits between strata without any of them changing. Strata whose GISTIC run is missing are listed as such rather than dropped silently, because an absent row and a null row are different statements.

if (!have_cat) {
